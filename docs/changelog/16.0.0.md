### ADDON_LOAD

:::: tip VERSION: <Badge type="warning" text="16.0.00.46" /> <Badge type="success" text="Release" />
- <Badge type="danger" text="Удалено" />
    - `common.StateLoadManagedAddonGroup`
    - `common.StateUnloadManagedAddonGroup`
- <Badge type="warning" text="Изменено" />
    - [common.StateLoadManagedAddon](/api/category/common/function.common.StateLoadManagedAddon.md)
    - [common.StateUnloadManagedAddon](/api/category/common/function.common.StateUnloadManagedAddon.md)
    - [common.GetStateManagedAddons](/api/category/common/function.common.GetStateManagedAddons.md)
    - [EVENT_ADDON_LOAD_STATE_CHANGED](/api/events/events.EVENT_ADDON_.md#event-addon-load-state-changed)
- <Badge type="success" text="Добавлено" />
    - [common.StateReloadManagedAddon](/api/category/common/function.common.StateReloadManagedAddon.md)
    - [ADDON_STATE_*](/api/constants/constants.ADDON_STATE.md)

::: details Подробнее
Изменяется система загрузки / выгрузки аддонов. Теперь сриптовая выгрузка происходит с  задержкой в 2 кадра.
Теперь нельзя менять статус аддона в процессе загрузки / выгрузки, в случае попытки действие не будет выполнено. При успехе действия API возвращают `true`, при провале `false`, при критической ошибке `nil` (но это почти невозможно).

Для перезагрузки введена отдельная API [common.StateReloadManagedAddon](/api/category/common/function.common.StateReloadManagedAddon.md) (параметры идентичны существующим).

- В [common.GetStateManagedAddons](/api/category/common/function.common.GetStateManagedAddons.md) вместо поля `bool` `isLoaded`, появляется поле [state](/api/constants/constants.ADDON_STATE.md).
- В [EVENT_ADDON_LOAD_STATE_CHANGED](/api/events/events.EVENT_ADDON_.md#event-addon-load-state-changed) вместо полей **`loading`** (`bool`), **`unloading`** (`bool`), появляется поле [state](/api/constants/constants.ADDON_STATE.md).
:::

### UIAddon

:::: tip VERSION: <Badge type="warning" text="16.0.00.46" /> <Badge type="success" text="Release" />
- UIAddon
- [common.GetAddonInfo](/api/category/common/function.common.GetAddonInfo.md)

::: details UIAddon
Из UIAddon удалены поля:
- `localizedNameFileRef`
- `localizedDescFileRef`
- `addonGroups`
- `addon_date`

Добавлено поле `userAddonInfo` - структура с полями:
- `name` - TextFileRef - аналог localizedNameFileRef
- `description` - TextFileRef - аналог localizedDescFileRef
- `license` - TextFileRef - interface future use
- `sourceLink` - TextFileRef - interface future use
- `supportLink`  - TextFileRef - interface future use
- `author` - string - interface future use
- `version` - string - для логгирования / interface future use
- `apiVersion` - int32_t (-1) - interface future use
- `buildTime` - int64_t (0) - для логгирования
- `useCommonScripts` - boolean (false) - загружать ли `CoreScriptsUserMods` (`AddonBase`, `ClassesImplementation`, `AdvEvent`, `WidgetCore`, `WidgetBaseClasses`)
:::

::: details common.GetAddonInfo
В common.GetAddonInfo появился обязательный агрумент - имя аддона для которого нужно получить информацию.

Также изменился формат вывода: в случае провала (аддон не найден) `false`, в случае успеха - таблица с полями:
- `state` - AddonState  - текущее состояние аддона
- `rawSysName` - string - системное имя аддона как в ресурсе
- `sysName` - string - системное имя аддона с учетом префиксной формы для пользовательских аддонов
- `userAddon` - bool - является ли аддон пользовательским
- `managed` - bool - можно ли аддон загружать /  выгружать, для пользовательских всегда `true`
- `autoStart` - bool - автозапуск аддона (для пользовательских всегда `false`, запуск должен быть разрешен встроенным аддон-менеджером)
- `useCommonScripts` - bool - загружаются ли `CoreScripts` для данного аддона

--- Часть только для пользовательских аддонов, напрямую из UIAddon.userAddonInfo ---

- `name` - wstring
- `description` - wstring
- `license` - wstring
- `sourceUrl` - wstring
- `supportUrl` - wstring
- `author` - string
- `version` - string
- `apiVersion` - int32_t
- `buildTime` -  int64_t

### common.RegisterEventHandler

::: tip VERSION: <Badge type="warning" text="---" /> <Badge type="success" text="Release" />
- common.RegisterEventHandler
- common.UnRegisterEventHandler

Удалена поддержка типа фильтра `objectId`, теперь фильтром может быть только таблица вида `string` - `value`, где `value` - это `bool`, `number`, `string`, `wstring`, `indexableUserdata`.

**ЖУТКОЕ КОЛДУНСТВО:** 

Добавлен опциональный параметр `(un)registerPersonalEvent` - bool (default true) - не **(де)регестрировать** `objectId` из таблицы фильтра в персональные эвенты.

Использовать только при необходимости высокой производительности в хорошо протестированном коде.

:::

::: success VERSION: <Badge type="warning" text="---" /> <Badge type="success" text="Release" />
Новое API:

- [common.EnablePersonalEvent](/api/category/common/function.common.EnablePersonalEvent.md)
- [common.DisablePersonalEvent](/api/category/common/function.common.DisablePersonalEvent.md)

Параметры:
- `string` - имя эвента
- `objectId` - ид сущности для регистрации персональных эвентов.

(де)регистрировать обработку персональных событий для пары событие-сущности.

Каждая пара является счетчиком, ограничение - не более 10 на аддон (то есть число разных хендлеров на один и тот же эвент с одним и тем же фильтром если в терминах классической регистрации эвентов), 200 глобально.

Защита от ухода ниже 0 имеется.

По умолчанию автоматически (де)регистрируются пары из фильтров при (де)регистрации событий.

**ЖУТКОЕ КОЛДУНСТВО:** 

Для некоторых событий (`EVENT_OBJECT_BUFF_ADDED` и тп) событие глобально формируется только есть хотя бы одна запись персональных эвентов. Использовать только при необходимости высокой производительности в хорошо протестированном коде.
:::
